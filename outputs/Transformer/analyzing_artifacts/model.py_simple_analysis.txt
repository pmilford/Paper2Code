Below is the detailed logic analysis for the model.py module, which is responsible for constructing the TransformerModel class and its supporting submodules. This module must faithfully reproduce the “Attention Is All You Need” architecture using PyTorch and use the configuration parameters defined in config.yaml.

────────────────────────────────────────
1. OVERALL STRUCTURE

• The TransformerModel class represents the full encoder–decoder network. Its public API includes:
 – __init__(params: dict): Initializes the model using the parameters (such as d_model, d_ff, num_layers, num_heads, dropout, etc.) extracted from the configuration (differentiating “base” vs. “big” variants).
 – forward(src: Tensor, tgt: Tensor, src_mask: Tensor, tgt_mask: Tensor) -> Tensor: Runs the forward pass through the encoder and decoder stacks, returning the output logits (before softmax) for training.
 – generate(src: Tensor, src_mask: Tensor) -> Tensor: Implements auto-regressive inference (e.g., greedy decoding) by first encoding the source and then iteratively calling the decoder until an end-of-sequence token is generated or the maximum length (input length + offset) is reached.

• The model uses shared token embeddings for the source and target sequences (and later ties these with the pre-softmax projection). All word embeddings are scaled by √(d_model).

────────────────────────────────────────
2. EMBEDDING AND POSITIONAL ENCODING

• Token Embeddings:
 – Create an nn.Embedding layer (or two if not sharing, but per paper they are tied) for converting input token indices into continuous vectors.
 – Multiply the embedding outputs by sqrt(d_model) (as specified in the paper) to stabilize the scale.

• Positional Encoding:
 – Implement a “PositionalEncoding” module that computes sinusoidal positional encodings.
 – Use the formulas:
  PE(pos, 2i) = sin(pos / (10000^(2i/d_model)))
  PE(pos, 2i+1) = cos(pos / (10000^(2i/d_model)))
 – These encodings are added to the token embeddings so that the model can glean information about the position of each token.
 – (Optionally, the design allows for a learned positional embedding variant to be added later if needed, but by default the sinusoidal version is used.)

────────────────────────────────────────
3. ENCODER STACK

The encoder is composed of a stack of N layers (N is read from the configuration; e.g., 6 for “base”):

• Each EncoderLayer has 2 main sub-layers:
 1. Multi-head Self-Attention:
  – Implements scaled dot-product attention.
  – Projects the input into queries, keys, and values via learned linear transformations.
  – Splits the results into h heads (with h set by num_heads in the config; for “base” h = 8) and computes attention for each head.
  – Computes the scaled dot-product attention: scores = (Q @ Kᵀ) / sqrt(d_k), applies an optional mask (if provided), computes softmax over scores, then multiplies by V.
  – The outputs across heads are concatenated and passed through a final linear projection.
 2. Position-wise Feed-Forward Network (FFN):
  – Consists of two linear layers: the first maps from d_model to d_ff (e.g., 512 → 2048 for “base”), followed by a ReLU activation, and the second maps from d_ff back to d_model.
  – Dropout is applied after the ReLU (and optionally after the second linear layer before adding the residual).

• Residual Connections & Layer Normalization:
 – Each sub-layer (both the multi-head attention and the FFN) is wrapped with a residual connection (i.e., the input is added to the output of the sub-layer) followed by layer normalization.
 – Dropout is applied to the sub-layer output before the addition.

• Implementation:
 – The encoder stack is built as an nn.ModuleList of encoder layers.
 – Each EncoderLayer itself will define within its forward() method the sequential application: attention sub-layer → residual add & norm → FFN sub-layer → residual add & norm.

────────────────────────────────────────
4. DECODER STACK

The decoder is also a stack of N layers (again, usually 6 for “base”) but each DecoderLayer contains three sub-layers:

• Sub-layer 1: Masked Multi-head Self-Attention:
 – Similar to the encoder’s self-attention but includes a masking mechanism that prevents a token from attending to future tokens. This ensures the auto-regressive property during training and inference.
  
• Sub-layer 2: Multi-head Encoder-Decoder Attention:
 – Uses multi-head attention where the query comes from the decoder’s previous sub-layer output, and keys and values come from the encoder’s final outputs.
 – This allows each position in the decoder to attend to all positions in the source sequence.

• Sub-layer 3: Position-wise FFN:
 – Identical in structure to the FFN in the encoder.

• Each sub-layer is followed by dropout, a residual connection, and subsequent layer normalization.

• Implementation:
 – The decoder stack is also an nn.ModuleList of decoder layers.
 – The decoder’s forward() method uses the source context from the encoder (computed beforehand) when performing the encoder-decoder attention.

────────────────────────────────────────
5. MULTI-HEAD ATTENTION & SCALING

• Multi-Head Attention Module:
 – This module implements the attention mechanism broadcast across multiple heads.
 – It first linearly projects the input x into Q, K, and V with separate nn.Linear layers.
 – The total d_model dimension is split into h parts so that each head operates in dimension d_k = d_model/h.
 – After computing scaled dot-product attention for each head, the outputs are concatenated along the feature dimension.
 – A final linear layer is applied to combine the concatenated head outputs.
 – The scaling factor used in attention is 1/√(d_k) (as per the paper) to counteract large dot-product magnitudes.

• The implementation uses PyTorch tensor reshaping to split and combine the head dimensions in an efficient manner.

────────────────────────────────────────
6. FEED-FORWARD NETWORK (FFN)

• Position-wise FFN Module:
 – Consists of two linear transformations with a ReLU in between.
 – The first linear layer maps the d_model-dimensional input to a higher-dimensional space (d_ff) and then applies ReLU.
 – The second linear layer maps the output from the hidden size d_ff back to d_model.
 – Dropout is applied after the ReLU activation.
 – Each FFN sub-layer is wrapped in a residual connection and followed by layer normalization.

────────────────────────────────────────
7. FINAL OUTPUT AND SHARED PARAMETERS

• Output Linear Projection:
 – After the decoder stack, a final linear layer projects the output to the vocabulary size.
 – In keeping with the paper, the weights of this output layer are tied with the token embeddings.
  
• Shared Weights:
 – The source and target embeddings are shared. This is achieved by instantiating a single embedding matrix and using it for both input conversions and later for pre-softmax linear transformation.

────────────────────────────────────────
8. AUTO-REGRESSIVE GENERATION (generate)

• The generate() Method:
 – Designed for inference.
 – First, the source tokens are passed through the embedding layer and positional encoding, then processed by the encoder to get context representations.
 – A loop is then started to auto-regressively generate target tokens:
  – Begin with an initial token (typically a start-of-sequence token).
  – At each iteration, the current target sequence and its corresponding mask (to prevent attending to future positions) are fed through the decoder, along with encoder outputs.
  – The next token is chosen—either by greedy decoding or by other search techniques (beam search is implemented in the Evaluator, so here a basic generation routine is acceptable).
  – The loop continues until an EOS token is generated or the maximum output length (input length + the configured offset, e.g. 50 for translation) is reached.

• The module must read the following parameters from the configuration:
 – Model variant ("base" or "big"): Determines which set of hyperparameters to use.
  – For “base”: d_model = 512, d_ff = 2048, num_layers = 6, num_heads = 8, dropout = 0.1.
  – For “big”: d_model = 1024, d_ff = 4096, num_layers = 6, num_heads = 16, dropout = 0.3.
• These configuration values dictate:
 – The dimensions for linear projections in attention.
 – The structure of the encoder and decoder (number of layers, head count, and inner dimensions).
 – The dropout rate used throughout the submodules.

 – Other common hyperparameters (although label smoothing is used in training and managed in trainer.py).
